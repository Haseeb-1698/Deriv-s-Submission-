A 7-stage triage pipeline
with a real Kimi-K2.6 inference path and a deterministic fallback.

Customer support tickets are loaded from tickets.json, deterministically normalized, classified by a single big prompt sent to the Moonshot Kimi-K2.6 API (OpenAI-compatible), handed to a human reviewer for override, and finally routed into per-team queues. A separate validate.py cross-checks every artifact against triage_config.json.

01  /  What this system does

Seven steps. Run in order. One after the other.

The program runs 7 steps, top to bottom. Each step finishes its job, saves the result to a file, and then the next step picks up from there. You can't skip a step — they always run in the same order. That's it.

Idea 1
The config file is the boss

The AI can suggest anything, but we don't just take its word for it. Every answer is double-checked against triage_config.json. If the AI picks something not on the list, we replace it with a safe default. The config decides where tickets go — not the AI.

Idea 2
Try the AI · fall back if it fails

First we try to call the real AI (Kimi-K2.6). If the API key is missing, the internet is down, or anything goes wrong, the program quietly switches to a simple keyword-matcher. It never crashes — you always get an answer.

Idea 3
A separate file checks the work

After the pipeline finishes, you run validate.py. It opens every file the pipeline wrote and confirms each one is correct. If everything's good, it prints ✅ VALIDATION PASSED. If anything is off, it tells you exactly what.

05  /  Validator architecture

validate.py · five independent checks, one verdict.

The validator never re-runs the pipeline. It only inspects artifacts on disk and compares them against triage_config.json. Each check is independent — if any check fails, the run ends with VALIDATION FAILED; otherwise it prints ✅ VALIDATION PASSED.

06  /  Verify it yourself

Copy-paste these into PowerShell.

The pipeline runs on Python 3.13 with only standard library. The openai and python-dotenv packages are optional — they are only used when the real Kimi call is desired. The .env file in this folder already holds KIMI_API_KEY and LLM_MODEL=kimi-k2.6.

Setup (one time)
Install optional deps
# PowerShell, from the project root:
pip install -r requirements.txt

Installs openai>=1.0 and python-dotenv>=1.0. Skip this if you just want the deterministic heuristic path — the pipeline still runs.

Run the full pipeline
interactive mode
python triage_pipeline.py
# at the override prompt, type either:
#   (Enter)                    → no overrides
#   T-1003,bug_report,high     → override one ticket
#   (Enter)                    → finish
Run non-interactive
pipe overrides via stdin
# PowerShell — pipes one override + empty line:
"T-1003,bug_report,high`n`n" | python triage_pipeline.py

# Bash equivalent:
printf 'T-1003,bug_report,high\n\n' | python triage_pipeline.py
Verify everything
expect ✅ VALIDATION PASSED
python validate.py
# exit code 0 = pass · 1 = fail
# tail the audit log:
Get-Content llm_calls.jsonl -Tail 1
# inspect the result:
Get-Content final_queue.json
